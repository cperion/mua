# Runtime outlines

`mua outline FILE [args]` executes a Mua file and prints the human labels reachable
from its returned values. This replaces the old source-comment outline and mandatory
comment lint. Generated objects can document themselves; source layout is irrelevant.

```sh
luajit mua.lua outline examples/outline.mua
```

```text
Editor  #1
├─ save  Save the current document  ƒ  #2  examples/outline.mua:8
└─ themes  Available themes  #3
   ├─ 1  Light  #4
   ├─ 2  Dark  #5
   └─ 3  Sepia  #6

6 labeled values · 1 callable
```

Use `label "description" value` to attach human identity and `label_of(value)` to read
it. Labels are not ordinary fields, semantic IDs or dispatch keys. See
[syntax](syntax.md) for the metadata protocol. Label useful functions and vocabularies
where they are constructed; labels need not be repeated on every contained value.
Named builtins (`checker`, `family`, `struct`, `oneof`, `ffistruct`, and passes) supply
labels automatically. Their semantic dispatch names remain independent of relabeling.

## Real code, not just a demonstration

```sh
# The compiler's library mode returns its labeled stages without running the demo.
luajit mua.lua outline examples/lisp.mua library

# Validation and ownership can each be inspected directly.
luajit mua.lua outline bui/ui/check.mua
luajit mua.lua outline bui/ui/scope.mua

# Composed exports, including descriptors generated by the widget catalog builder.
# This module loads no native window and invokes no widget actions.
luajit mua.lua outline examples/bui/outline.mua
```

The compiler exposes its reader, checker, evaluator, optimizer, emitter and factories.
The BUI outline includes validation functions, lifetime operations and generated control
kinds. Their labels are attached where those values are constructed, not maintained in
a separate documentation registry.

## Execution contract

- **The file executes normally, including side effects.** Only run trusted code.
  Printing, I/O, errors and long-running initialization are not suppressed or sandboxed.
- Arguments reach the file as `...` and `arg`; Mua `require` works as for ordinary runs.
- All returned values are roots, including values after nil returns. No return or no
  reachable labels prints `No labeled values returned.` Private locals are not inspected.
- The walker reads raw table values. It does not invoke functions, `__index`, `__pairs`,
  `__tostring`, or walk metatables. Functions, userdata and FFI cdata are leaves.
- Unlabeled containers are retained only when they lead to labeled values. Other
  unlabeled fields are omitted. Keys supply paths; labels supply descriptions.
- Numeric and string keys are sorted within their types. Opaque keys are displayed as
  `<table key>`, etc.; their relative order is unspecified. Table keys themselves are
  not traversed. Control characters in labels and string keys are escaped.
- Lua functions show `file:line` from `debug.getinfo(fn, "S")`. This is the function's
  definition, not the label attachment site; generated closures may point into their
  factory. Tables have no debug source location. C functions and missing debug metadata
  omit locations. The API accepts `locations = false` to hide them.
- Shared values and cycles use `↩ #N` references to the numbered first occurrence.
  Counts refer to unique reachable labeled values, not the number of paths to them.
- Display depth is capped at 32. Scanning more than 10,000 table entries fails explicitly;
  this bounds inspection, not the execution of the file. The Lua API
  `require('mua.outline').render(packed_returns, options)` accepts `max_depth` and
  `max_entries` overrides.

The command exits 0 on success and 1 for loading, execution or inspection errors.
`--help` describes the execution contract without running a file.

Spreading a vocabulary copies its entries, not its metatable label. The resulting
outline describes the actual constructed graph, not the history of its composition.
